# App DB & Drizzle Schema — Plan

**For this spec:** `[[spec]]`

## Approach

Port `db/schema.sql` 1:1 into a typed Drizzle schema living in `apps/api/src/db`,
treating the DDL as the diff oracle: every enum value/order, column type,
nullability, default, FK `ON DELETE` action, UNIQUE constraint, and named index
(including the two `DESC` ones) must round-trip. Drizzle has no native `bytea`, so a
dedicated `customType` emits `bytea` with a `Buffer` TS type — the one place a
careless mapping could turn a secret column into `string`. The `jsonb`
`exposed_tables.columns` is typed by an `ExposedColumn` shape that lives in
`packages/shared` (the single cross-boundary definition), imported by the schema.

Migrations are generated by `drizzle-kit generate` into a committed
`apps/api/drizzle/` folder and applied by a tiny programmatic migrator
(`drizzle-orm` `migrate()`), so the spec-16 deploy runs them identically. A seed
script writes one demo org + owner user (+ optional stub connections with OBVIOUS
placeholder bytea, never a real encrypted blob — encryption is spec 02),
idempotently via fixed UUIDs + `onConflictDoNothing`.

Verification is two-layered: an always-on Vitest test introspects the schema with
`getTableConfig`/`enumValues` (no DB needed — asserts bytea→`bytea`+NOT NULL,
jsonb shape, the four denormalized `org_id` columns, the SET-NULL/NO-ACTION FK
exceptions, enum value order); and an env-gated live test (gated on `DATABASE_URL`)
that creates a throwaway database, runs the committed migration, asserts the 4
enums + 11 tables + a DESC index exist, then drops it. The live test SKIPS in the
default `pnpm test` (CI-safe) and is run green once against local Docker this
iteration (recorded `LIVE-VERIFICATION-PENDING`).

## Architecture

```
apps/api/
  drizzle.config.ts          # drizzle-kit: schema path, out=./drizzle, dialect=postgresql, DATABASE_URL
  drizzle/                   # generated, committed SQL migrations + meta
  src/db/
    bytea.ts                 # customType<Buffer> -> emits `bytea`
    schema.ts                # 4 pgEnum + 11 pgTable (FKs, indexes, uniques) — the 1:1 port
    client.ts                # makeDb(url): { db, pool } via drizzle-orm/node-postgres
    migrate.ts               # db:migrate — programmatic migrator (fail-fast on missing DATABASE_URL)
    seed.ts                  # db:seed — idempotent demo tenant, placeholder bytea
    schema.test.ts           # always-on structural asserts + env-gated live migrate smoke
packages/shared/src/
    db-contracts.ts          # enum unions (UserRole, ConnectionStatus, MessageRole, LogStatus) + ExposedColumn
```

Type boundary (non-circular realization of the resolved 00/01 decision): the
Drizzle schema and its `$inferSelect`/`$inferInsert` row types stay in `apps/api`
(server-only — they carry `Buffer` and internal columns the web must never
consume). `packages/shared` owns the cross-boundary *primitives* — the enum string
unions and the `ExposedColumn` jsonb shape — which the schema imports. `shared`
never imports from `apps/api` (that would be a circular workspace dependency).

## File Structure

- `packages/shared/src/db-contracts.ts` + barrel export — enum unions + `ExposedColumn`.
- `apps/api/src/db/bytea.ts` — `bytea` customType (Buffer).
- `apps/api/src/db/schema.ts` — enums + tables + indexes + uniques; inline comments
  marking the denormalized `org_id` (invariant 1) and the FK delete-action exceptions.
- `apps/api/src/db/client.ts` — `makeDb(databaseUrl)`.
- `apps/api/src/db/migrate.ts` / `seed.ts` — ops scripts (tsx).
- `apps/api/drizzle.config.ts` — drizzle-kit config.
- `apps/api/drizzle/*` — generated migration(s) (committed).
- `apps/api/src/db/schema.test.ts` — structural + live tests.
- `apps/api/package.json` — deps (`drizzle-orm`, `pg`, `dotenv`) + dev
  (`drizzle-kit`, `@types/pg`) + scripts `db:generate` / `db:migrate` / `db:seed`.
- Root `package.json` — convenience `db:*` passthroughs filtered to `@lumen/api`.
- `context/learnings/commands-catalog.md` — record `db:generate/migrate/seed`.

## Phase Ordering

1. **shared contracts** — enum unions + `ExposedColumn` (schema depends on these).
2. **deps + bytea + schema** — add deps, `bytea` customType, full `schema.ts` port.
3. **config + client + migrate + seed** — drizzle.config, client, ops scripts.
4. **generate + verify** — `db:generate`; diff emitted SQL vs `db/schema.sql`
   clause-by-clause; commit the migration.
5. **tests + live run** — structural test (always-on) + env-gated live smoke; run
   the live smoke green against Docker; `db:migrate` + `db:seed` against Docker.
6. **gates + ship** — full suite green; commands-catalog; mark Shipped.

## Risks / Open Decisions

- bytea→string drift: dedicated customType + a test asserting `getSQLType()==='bytea'`
  and NOT NULL, and a grep of the generated migration for `bytea`.
- drizzle-kit emitting FK actions / DESC ordering / enum order differently: diff the
  generated SQL against `db/schema.sql` before committing; the four SET-NULL/NO-ACTION
  FKs are asserted in the structural test.
- Denormalized `org_id` "looks redundant": inline invariant-1 comments + a test
  asserting those four `org_id` columns exist and are NOT NULL.
- Seed mistaken for real secrets: obvious placeholder bytes + comment; stub rows optional.
- Circular workspace dep if `shared` tried to import the schema: avoided — `shared`
  holds only primitives; inferred row types stay in `apps/api`. (Recorded in plan.)
- drizzle-orm/drizzle-kit version pairing: pin a known-compatible pair; if `generate`
  errors on a mismatch, adjust to the installed pair this iteration.
